# 2026-08-26 · LR/SC 不 fault 的发现与 amocas.w 方案

> 板子：RP2350A-Minimal · 内核：linux 7.2 riscv32 noMMU M-mode + AMO 模拟器
> 现象：修好非对齐读后，boot_cpu_init 的 5 条 AMO 全部被模拟（`ok`），但内核随后**静默卡死**，无任何新输出；GDB 抓到 PC 停在 `prb_reserve`（printk 环形缓冲区）的 LR/SC cmpxchg 循环里（`lr.w` → `bne` → `sc.w.rl` → `bnez` 重试）。

## 关键发现（与 S3-01 最初假设相反）

**LR/SC 在 PSRAM 上不会 fault——`sc.w` 只是静默返回失败（1），所以任何 LR/SC 重试循环都会永远空转。**

依据：RP2350 datasheet 2.1.6（Global Exclusive Monitor）：

> "Exclusive accesses are only supported on SRAM. The system treats exclusive accesses to other memory regions as normal reads and writes, reporting exclusivity failure to the originating PE, for example by a non-zero return value from an Arm strex instruction."

对比：
- **AMO**（amoadd/amoor/amoswap…）：Hazard3 实现为"排他读-写对，重试直到写成功"，PSRAM 上永远失败 → 报 mcause=6/7 → 可被模拟器拦截（已实现）。
- **LR/SC**：LR 是普通读 + 监视器打标；SC 检查监视器，不支持就**返回失败**（RISC-V 语义允许），**不产生异常** → 模拟器无从拦截。

因此 S3-01 笔记里"LR/SC 在 PSRAM 上同样 fault，所以一并模拟"的假设是错的：模拟器的 LR/SC 分支从未被真正触发过。

## 触发点

`start_kernel` 第一条打印 `pr_notice("%s", linux_banner)`（在 `setup_arch` 之前）→ `printk` → `prb_reserve` 用 `cmpxchg`（LR/SC）保留环形缓冲区描述符 → 死循环 → 静默。

## 修复方案：让 cmpxchg 走 amocas.w（Zacas）

`amocas.w` 是 AMO 编码（opcode 0x2f, funct5=00101），会 fault（Hazard3 没有 Zacas 解码器 → mcause=2 非法指令）→ 可被模拟器拦截。

改动（未提交，测试用）：

1. `arch/riscv/include/asm/cmpxchg.h`：`__arch_cmpxchg` 的 amocas 路径条件加 `|| IS_ENABLED(CONFIG_RISCV_AMO_EMULATION)`——**编译期强制**走 amocas。原因：原条件 `riscv_has_extension_unlikely(ZACAS)` 依赖运行时 hwcap，而 hwcap 在 `setup_arch`（`riscv_fill_hwcap`）里才解析，第一次 printk 时必为 false。
2. `arch/riscv/kernel/amo-emu.c`：
   - 异常过滤允许 `EXC_INST_ILLEGAL`（2），但只放行 funct5=0x05（amocas）的非法指令；
   - 新增 amocas.w 模拟：`rd` 既是输入（期望值）又是输出（旧值），`old == expected` 时写 `rs2`，`rd = old`；
   - funct3 必须为 010（word）。

验证：新内核 `prb_reserve` 已无反汇编到 `lr.w/sc.w`，全部是 `amocas.w.aqrl`。

## 已知边界

- 1/2 字节 cmpxchg/xchg（`__arch_cmpxchg_masked` / `__arch_xchg_masked`）仍走 LR/SC（Zabha 未开）——若启动路径用到会再次静默空转，届时再处理。
- amocas 只在 PSRAM 窗口内模拟（当前内核数据全在 PSRAM）。
- 若内核将来把数据放到 SRAM（0x20000000），cmpxchg 走 amocas 会因非法指令进模拟器、但地址不在 PSRAM 而被拒——届时需放宽 amocas 的地址范围。
