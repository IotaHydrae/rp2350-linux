# 2026-08-25 · S3-01 真板首跑：PSRAM 拷贝损坏 + 模拟器未拦截

板子：RP2350A-Minimal · 内核：linux 7.2 + AMO 模拟器（`ee2a9d82b`）· 工具：OpenOCD + GDB

## 现象

bootloader 拷贝正常（3MB、首字节 `b1 a8 00 00`），跳转后内核仍零输出。

## 诊断（三路对比）

1. **flash 正确**：`x/8wx 0x101A5644`（分区 0 @ 内核偏移 0x195644）== 镜像文件（`0x000462b7 ...`）。
2. **PSRAM 损坏**：`x/8wx 0x11195644` ≠ 文件——隔字损坏，坏值全是 `0x11xxxxxx` 形式的内核地址（含 `__global_pointer$` 运行时地址 0x112570e4），像"运行期数据被写进 .text"或"拷贝经写回缓存丢写留旧数据"。
3. **第一异常仍是 AMO**：hbreak `handle_exception`（新内核 0x111955f0）→ reset → 第一现场 `mcause=0x7`、`mepc=0x1100ebc0` = `set_cpu_online` 的 `amoor.w.aqrl`（新内核偏移 0xebc0）。

推论：模拟器代码和钩子都在 vmlinux 里（`do_trap_error` 中 `jal try_amo_emulation` 已验证），但**它读到的是 PSRAM 里被损坏的指令字节 → opcode 不匹配 → 返回 false → 回落 die**。根因是拷贝/缓存路径损坏，不是模拟器逻辑。

## 另一个发现（QEMU 对照，暂缓处理）

旧内核（00）用无 clint 的自定义 DTB 在 QEMU 里**同样崩在 `get_cycles64`**（load fault，GOT 间接访问 `clint_time_val`）：

- noMMU 的 `relocate_kernel()` 是空操作（`setup_vm` 用链接地址 0 算 `reloc_offset=0`），GOT 槽不重定位。
- M 模式 `get_cycles()` 通过 GOT 读全局 `clint_time_val`（timex.h）→ 一旦调用就崩。
- S2 没撞上是因为 QEMU DTB 有 clint 节点，clint 驱动在自己的编译单元里 PC 相对访问并接管了 sched_clock，绕开了 arch 路径。
- **用户拍板暂不动内核**：等加 clint 节点时再处理（届时 clint 驱动同样能接管；或修 noMMU 重定位用 `la` 取运行时基址）。

## 结论与下一步

首要问题 = **bootloader 3MB 拷贝损坏部分 PSRAM 区域**（flash 对、PSRAM 错）。修法候选：拷贝走 uncached 窗口 + 跳转前 invalidate XIP 缓存；或拷贝后整段校验；或查写回缓存/PSRAM 时序。待定，先记录。
