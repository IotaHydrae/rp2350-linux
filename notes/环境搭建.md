# 环境搭建速查

## RISC-V 裸机工具链（pico-sdk 编译固件用）

官方来源：树莓派 `pico-sdk-tools` releases（riscv-toolchain-14）。下载并解压：

```bash
mkdir -p ~/toolchain && cd ~/toolchain
wget -c https://github.com/raspberrypi/pico-sdk-tools/releases/download/v2.0.0-5/riscv-toolchain-14-x86_64-lin.tar.gz
tar xzf riscv-toolchain-14-x86_64-lin.tar.gz -C ~/toolchain
```

要点：

- 压缩包解压后**顶层就是 `bin/`**（内含 `riscv32-unknown-elf-gcc` 等），不用再进子目录；
- 验证：`ls ~/toolchain/bin/riscv32-unknown-elf-gcc`；
- pico-sdk 通过 `PICO_TOOLCHAIN_PATH` 找编译器，可接受的三元组：`riscv32-pico-elf` / `riscv32-unknown-elf` / `riscv32-corev-elf` / `riscv-none-elf`（本工具链是 `riscv32-unknown-elf`）；
- 本机安装位置：`/home/developer/toolchain` → `export PICO_TOOLCHAIN_PATH=/home/developer/toolchain`；
- GitHub 直连可能很慢：可以用加速镜像，但下载后务必确认 `riscv32-unknown-elf-gcc` 存在（最好核对 sha256）；
- 压缩包约 850MB，解压完成后可以删掉省空间（`rm ~/toolchain/riscv-toolchain-14-x86_64-lin.tar.gz`）。

## 完整构建环境（本机现状，2026-08-21）

| 项 | 值 |
|---|---|
| PICO_SDK_PATH | `/home/developer/raspberrypi/pico-sdk`（2.3.0） |

| PICO_BOARD | `rp2350a_minimal`（自定义，仓库 `boards/`） |
| PICO_BOARD_HEADER_DIRS | `<仓库>/boards` |
| 内核交叉编译器 | `riscv64-linux-gnu-gcc`（S2 编内核用，系统自带 /usr/bin） |
| QEMU | `qemu-system-riscv32`（10.2.1） |
| 其他工具 | picotool 2.3.0、openocd、dtc、cmake、ninja |
| 构建入口 | 仓库根 `make`（封装 cmake + ninja） |

标准构建命令（等价于 `make`）：

```bash
cd /home/developer/iotahydrae/rp2350-linux
PICO_TOOLCHAIN_PATH=/home/developer/toolchain \
cmake -DPICO_SDK_PATH=/home/developer/raspberrypi/pico-sdk \
      -DPICO_PLATFORM=rp2350-riscv \
      -DPICO_BOARD=rp2350a_minimal \
      -DPICO_BOARD_HEADER_DIRS=$(pwd)/boards \
      -B build -G Ninja
ninja -C build
```

S2 内核 QEMU 测试脚本：`s2/run-qemu.sh`（`-bios none` + earlycon/console 已配好；退出 Ctrl-A X）。

## 内核构建（完整 defconfig 方式，S3+）

**不要再使用 merge_config 碎片**（`nommu_virt_defconfig` + 碎片叠加）——已踩过的坑：

1. `merge_config.sh` 内部用 `alldefconfig` 重建配置（缺失项填默认值），RISC-V 的 `MMU` 默认是 `y`，会把 defconfig 的 `MMU=n` 盖掉 → M 模式/AMO 模拟器（依赖 `!MMU`）全被丢弃。
2. `savedefconfig` 只保留**非默认值**——base ISA 的 choice 默认是 **RV64I**，所以 `CONFIG_ARCH_RV32I=y` 这种"恰好是我们要、但不是默认"的项会被静默丢掉，编出 RV64 内核（在 RV32 核上静默卡死，2026-08-26 踩过）。

正确做法：**每个真板工程一份完整 defconfig**（工程内真源，`savedefconfig` 导出），构建时拷进构建目录当 `.config` 种子再 `olddefconfig`：

```bash
# 工程根目录一键构建（推荐）
make kernel-s3-00    # s3/00_amowall（无 AMO 模拟器，复现撞墙）
make kernel-s3-01    # s3/01_earlycon（含 AMO/amocas 模拟器）

# 手动等价命令（以 01 为例）
cd /home/developer/linux-7.2
cp <工程>/s3/01_earlycon/rp2350_minimal_defconfig build-rv32/.config
make ARCH=riscv CROSS_COMPILE=riscv64-linux-gnu- O=build-rv32 olddefconfig
make ARCH=riscv CROSS_COMPILE=riscv64-linux-gnu- O=build-rv32 -j$(nproc) Image
cp build-rv32/arch/riscv/boot/Image <工程>/s3/01_earlycon/kernel-Image
```

defconfig 位置：`s3/00_amowall/rp2350_amowall_defconfig`、`s3/01_earlycon/rp2350_minimal_defconfig`（内核树 `arch/riscv/configs/rp2350_minimal_defconfig` 有一份已提交快照，构建不依赖它）。

## ⚠️ 推送 GitHub 卡住的坑（2026-08-21 已解决）

现象：`git push origin main` 在 `Writing objects: 100%` 之后一直挂住不结束。

排查：SSH 认证正常（`ssh -T git@github.com` 返回成功）、`git ls-remote` 能完成但很慢（13 秒）、仓库本身正常（12MB / 273 对象）。结论是**国内网络到 GitHub 的 SSH 大包传输被限流**，小请求能过、大上传卡死。

解决：**换网络（WiFi）** 后一次成功。备选方案（未使用）：SSH 走 443 端口（ssh.github.com）、换 HTTPS + PAT、`protocol.version=1`、重试。

教训：先分辨「连接问题 vs 传输问题」——`ssh -T` 验证认证、`git ls-remote` 验证协议、`--progress` / `ssh -vv` 定位卡点；GitHub 国内限流是常态，大文件推送用 LFS 或外部管理更稳。
