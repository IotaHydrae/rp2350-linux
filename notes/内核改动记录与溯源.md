## 提交 1：`ee2a9d82b` — AMO/LR/SC 模拟器初版

**完整 id**：`ee2a9d82bc947972c82e3a1c8864ec186577f82d`

**文件**：

```text
arch/riscv/Kconfig               |   9 +++     （CONFIG_RISCV_AMO_EMULATION）
arch/riscv/include/asm/amo-emu.h |  16 ++++    （接口声明，未开选项时 inline false）
arch/riscv/kernel/Makefile       |   2 +       （编译 amo-emu.o）
arch/riscv/kernel/amo-emu.c      | 171 +++++    （模拟器本体）
arch/riscv/kernel/traps.c        |   4 +       （do_trap_error 挂钩）
```

**做了什么**：在异常路径里加一个"软件执行器"。`do_trap_error()` 开头先调 `try_amo_emulation(regs)`：如果故障指令是 AMO/LR/SC 且目标地址在 PSRAM 窗口（0x11000000-0x11800000），就用普通 load/store 完成读-改-写，然后 `mepc += 4` 假装指令执行完；不认识的异常照常走 die/信号路径。模拟器内部：`reg_by_num()` 把指令里的寄存器编号映射到异常现场、按 funct5 解码九种 AMO 运算、用 `emu_res_addr` 软件跟踪 LR/SC 预约。

**为什么这么改**：RP2350 的 Hazard3 把 AMO 实现为"排他读+写"对，而排他监视器只支持 SRAM（手册 2.1.6）。内核跑在 PSRAM 上，第一条原子操作（`boot_cpu_init() → set_cpu_online()` 的 `amoor.w`）就触发 Store/AMO Fault（mcause 7），早于任何打印——S3-00 的"静默卡死"就是这个。既然硬件做不了，就让 trap 路径软件模拟。**原子性安全**的论证：单核（SMP=n）+ M 模式 trap 期间中断被硬件关掉，读-改-写中间不可能插进别的代码。

**当时的认知局限（重要）**：初版注释写"Any AMO/LR/SC ... raises a Store/AMO fault"——错误地假设 **LR/SC 也会 fault**。这个假设在 S3-01 被证伪（见 #2），也导致模拟器初版对 LR/SC 的模拟路径实际上没被真正触发过。

**关联记录**：`notes/学习记录/S3-00 · earlycon 工程：真板静默调试全过程.md`、`实验日志/2026-08-25_S3-00_AMO墙定位.md`

## 提交 2：`6860027b2` — 完成 AMO/amocas 模拟

**完整 id**：`6860027b2fc553485040a9ced75c20cd4af59bac`

**文件**：

```text
arch/riscv/include/asm/cmpxchg.h | 14 +++++++-  （32 位 cmpxchg 强制走 amocas.w）
arch/riscv/kernel/amo-emu.c      | 69 ++++++++  （半字取指 + amocas.w 模拟 + mcause 2）
```

**做了什么**：
1. `cmpxchg.h`：32 位 compare-and-swap 在 `CONFIG_RISCV_AMO_EMULATION` 下**无条件**用 `amocas.w`（不再等运行时 hwcap 检查——启动早期 hwcap 还没解析）；
2. `amo-emu.c`：取指从"直接读 u32"改成"两个 u16 半字拼装"；新增 `amocas.w` 模拟（比较-交换语义）；接受非法指令（mcause 2）入口。

**为什么这么改**：S3-01 真板发现手册 2.1.6 的完整含义——**LR/SC 不 fault**：`lr.w` 正常读、`sc.w` 静默返回失败（排他监视器把非 SRAM 访问当普通访问）。所有 LR/SC 重试循环因此永不退出。模拟器只在 trap 里工作，够不着"不 fault"的指令，所以必须把所有原子路径翻译成**会 fault 的 AMO**。`amocas.w`（Zacas 扩展）正是这个翻译目标：它是 AMO 编码会 fault，且 Hazard3 没有 Zacas 解码器，实际到异常时是**非法指令（mcause 2）**，模拟器一并处理。

取指改半字拼装的原因：C 扩展下 32 位指令可能从 2 字节边界开始（`mepc` 模 4 = 2），而 RP2350 对非对齐 32 位 load 返回 `0xf0000000` 垃圾值（S3-01 单独撞过）。两个必然 2 字节对齐的 `u16` 读拼装是安全做法。

**关联记录**：`实验日志/2026-08-26_S3-01_LRSC静默失败与amocas方案.md`、`notes/内核AMO模拟器详解.md`

## 提交 3：`c8bf5c2a3` — PL011 驱动允许 RISC-V 编译

**完整 id**：`c8bf5c2a32b958b4c15e1d79739bcf82378d5ab5`

**文件**：

```text
drivers/tty/serial/Kconfig | 2 +-
```

```kconfig
config SERIAL_AMBA_PL011
	tristate "ARM AMBA PL011 serial port support"
-	depends on ARM_AMBA
+	depends on ARM_AMBA || RISCV
```

**做了什么**：把 `SERIAL_AMBA_PL011` 的依赖从"仅 ARM"放宽为"ARM 或 RISC-V"。

**为什么这么改**：RP2350 的 UART0 是 ARM PrimeCell PL011（硬件 IP 是 ARM 的），但运行的内核是 RISC-V 架构。不加这行，驱动（以及它的 earlycon 注册表项）根本编不进内核，S3-01 的 earlycon 出字就无从谈起。

**关联记录**：`notes/学习记录/S3-01 · 从AMO墙到earlycon出字：完整踩坑历程.md`（PL011 未编译那一关）

## 提交 4：`24ad00dc9` — MTIME 临时补丁（已回退）

**完整 id**：`24ad00dc9b982cbcbfd4e90ce91883571794f7d7`

**文件**：

```text
arch/riscv/kernel/setup.c | 16 ++++++++
```

**做了什么**：`setup_arch()` 里写两行硬编码——`writel(0x0f, 0xd00001a4)`（SIO MTIME_CTRL 开 FULLSPEED）和 `clint_time_val = (u64 __iomem *)0xd00001b0`。

**为什么这么改（临时救火）**：S3-01 的 udelay 卡死。根因链：DTB 没有 clint 节点 → `clint_time_val` 保持 NULL → M 模式 `get_cycles()` 读地址 0（RP2350 上读 0 不 fault，返回垃圾）→ 校准循环空转。临时补丁强制 MTIME 走 150MHz FULLSPEED 并硬编码指针，让 `get_cycles()` 有真值可用。

**为什么必须回退**：它是"硬编码 + 写死 150MHz"的应急方案，不是正经驱动；时间基准绑死 sys_clk，bootloader 一改频率就错。S3-02 正式定时器驱动（#6）落地后立即回退。

**状态**：`5efd5517f` 中删除（16 行全部移除）。

**关联记录**：`实验日志/2026-08-26_S3-01_udelay定时器墙与临时timer补丁.md`、学习地图关键更正第 ② 条

## 提交 5：`a145f130e` — `rp2350_minimal_defconfig`

**完整 id**：`a145f130eb7beeff9c6d1a5d48404f9ab5aa9170`

**文件**：

```text
arch/riscv/configs/rp2350_minimal_defconfig | 69 ++++++++++++
```

**做了什么**：把内核配置从"碎片 fragment + merge_config"改成**一份完整 defconfig**（savedefconfig 导出），放进内核树的 `arch/riscv/configs/`。关键行：`CONFIG_ARCH_RV32I=y`、`# CONFIG_MMU is not set`、`CONFIG_RISCV_AMO_EMULATION=y`、`CONFIG_SERIAL_AMBA_PL011=y`、无 `CONFIG_CMDLINE_FORCE`。

**为什么这么改**：merge_config 碎片方案踩了两个坑（学习地图关键更正 ⑤⑥）：① `alldefconfig` 会用默认值重建配置，MMU 默认 y 会盖掉 `MMU=n`；② `savedefconfig` 导出会丢掉非默认的 `ARCH_RV32I`（RISC-V base ISA 默认 RV64I），编出 RV64 内核在真板上静默卡死。完整 defconfig 是唯一真源。**注意**：每个 S3 工程目录里还有一份同内容副本，那才是构建时拷进 build 目录的种子（`make kernel-s3-0x`），内核树这份是提交快照，构建不依赖它——因为用户要求"不要往内核里加更多 config"，后续工程的新配置只放工程内。

**关联记录**：学习地图关键更正 ⑤⑥、`notes/环境搭建.md`（merge_config 两坑）

## 提交 6：`5efd5517f` — SIO MTIME/MTIMECMP 定时器驱动

**完整 id**：`5efd5517f82e1f7db4dfac3fcf68a2da2b400d0b`

**文件**：

```text
arch/riscv/kernel/setup.c          |  16 ---   （回退 #4 临时补丁）
drivers/clocksource/Kconfig        |   9 ++    （CONFIG_RP2350_TIMER）
drivers/clocksource/Makefile       |   1 +     （timer-rp2350.o）
drivers/clocksource/timer-rp2350.c | 195 ++++  （驱动本体）
```

**做了什么**：新增 `timer-rp2350.c`，把 RP2350 SIO 里的平台定时器接进 Linux 时钟子系统：
- **clocksource**：读 64 位 MTIME（0x1b0/0x1b4，带手册要求的"高半重读防翻转"循环）提供时间基准；
- **clockevent**：写 MTIMECMP（0x1b8/0x1bc），按手册 3.1.8 的"全 1 → 高半 → 低半"序列避免假中断，到点触发标准 MTIP 中断；
- 中断用 `request_percpu_irq`（`riscv,cpu-intc` 的本地中断全是 percpu 类型）+ `DEFINE_PER_CPU` clockevent；
- 兜底检查/启动 tick generator（TICKS_RISCV_CTRL），不依赖 bootloader 行为；
- 同时删除 #4 的临时补丁。

**为什么这么改**：
1. **不能用现成 `timer-clint` 驱动**，三个硬伤：寄存器偏移写死（CLINT 的 MTIME @ +0xbff8、MTIMECMP @ +0x4000，RP2350 在 SIO 的 0x1b0/0x1b8）；强制要求 timer+soft 双中断（RP2350 软中断在 SIO 另一个寄存器）；`writeq` 低→高写比较器会触发假中断。
2. **时间基准选 1MHz tick 而不是 150MHz FULLSPEED**（用户决策"不要写死 sys_clock"）：SDK 启动时已用固定 clk_ref（12MHz）÷12 喂给 MTIME，恒 1MHz，与 bootloader 可调的 sys_clk 完全解耦，DTB `timebase-frequency = <1000000>` 写死是安全的。

**真板验证**：`rp2350-timer: timer running at 1000000 Hz` + `calibrate_delay ... lpj=4000` + 时间戳推进。

**关联记录**：`notes/学习记录/S3-02 · 定时器与中断链.md`、`实验日志/2026-08-27_S3-02定时器链验收.md`

## 提交 7：`87546b2fd` — 条件原子操作 amocas 化

**完整 id**：`87546b2fd81b3977af62d23ba72fe1aff5bc7859`

**文件**：

```text
arch/riscv/include/asm/atomic.h | 71 ++++++++++++
```

**做了什么**：`CONFIG_RISCV_AMO_EMULATION` 下，把 `arch_atomic_fetch_add_unless`、`arch_atomic_inc_unless_negative`、`arch_atomic_dec_unless_positive`、`arch_atomic_dec_if_positive` 四个"条件原子操作"从 LR/SC 内联改写为 `arch_cmpxchg`（amocas.w）循环；非模拟配置保持原 LR/SC 不变。

**为什么这么改**：S3-02 真板启动推进到 `Mountpoint-cache` 后必现卡死，GDB 抓到 pc 在 `deactivate_super()` 的 `atomic_dec_and_test` 底层 `arch_atomic_fetch_add_unless(v, -1, 1)`——又是一段 `lr.w/sc.w` 循环。#2 只把 **cmpxchg** 翻译成了 amocas，但这四个"有条件"原子操作（语义带 if，单条 AMO 表达不了，RISC-V 内核用 LR/SC 写）还留着 LR/SC，在 PSRAM 上静默失败死循环。这是 S3-01 那堵墙的残留，本提交补完。改完后反汇编确认 `deactivate_super` 生成 `amocas.w.aqrl`，启动一路推进到无 rootfs 的 VFS panic。

**遗留（记录在案）**：rv32 的 64 位原子（`CONFIG_GENERIC_ATOMIC64` 走 `cmpxchg64` LR/SC 路径）仍未收口，S3-02 未触发；若后续撞到，需把 64 位 cmpxchg 迁到 `amocas.d` 并扩展模拟器。

**关联记录**：`notes/学习记录/S3-02 · 定时器与中断链.md`（第六根枝）、`实验日志/2026-08-27_S3-02定时器链验收.md`、`notes/内核AMO模拟器详解.md`（第 7 节）

## 提交 8：`744aaf5d3` — RP2350 Xh3irq 外设中断控制器驱动

**完整 id**：`744aaf5d3`（`git show 744aaf5d3`）

**文件**：

```text
drivers/irqchip/irq-rp2350-xh3irq.c | 150 ++++  （驱动本体）
drivers/irqchip/Kconfig              |   5 +     （CONFIG_RP2350_XH3IRQ，带 prompt 供 defconfig 设置）
drivers/irqchip/Makefile             |   1 +     （irq-rp2350-xh3irq.o）
```

**做了什么**：S3-03 新增的 Xh3irq 中断控制器驱动（Hazard3 自定义，非标准 PLIC）：
- irq domain（52 线 linear）+ chip：mask/unmask 操作 MEIEA CSR 数组（低 5 位选窗口 irq/16，高 16 位数据 bit=irq%16）；
- chained handler（挂父中断 MIP.MEIP/cause 11）：`csrrs` 同指令读 MEINEXT + 写 UPDATE（让硬件更新 MEICONTEXT）→ `generic_handle_domain_irq` 分发 → 循环到 MSB（无中断）为止；
- 两个 RP2350 专用防护：**init 时清空 MEIEA**（复位不是全 0，IRQ 14 USBCTRL / IRQ 3 TIMER0 被发现已使能，会导致风暴）；**分发时无 handler 的 IRQ 直接 mask**（电平源在 handler 清源前一直 pending，无主中断会死循环）。

**为什么这么改**：S3-02 只建了本地中断（cpu-intc + MTIP），外设中断（UART、PIO、USB 等 52 条线）聚合到 MIP.MEIP，需要一个 irqchip 驱动把它们接进 Linux 中断子系统。Xh3irq 不是标准 PLIC（无 claim 寄存器、无 MMIO），只能按 CSR 数组语义写自定义驱动。

**真板验证**：MEIFA force 触发 IRQ 33 → MEINEXT 读出 33 → MEIP → cpu-intc → chained handler → 测试 handler 输出 `!`（TEMP 测试代码验证后删除）；启动日志 `interrupt-controller: 52 external interrupts mapped`、无 IRQ 14 风暴。

**关联记录**：`notes/学习记录/S3-03 · Xh3irq 外设中断.md`、`实验日志/2026-08-28_S3-03外设中断验收.md`
