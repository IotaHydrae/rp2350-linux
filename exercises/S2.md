# S2 练习题：QEMU 跑真内核

> 复习材料：`notes/学习记录/S2 · QEMU 跑真内核.md`、`notes/实验日志/2026-08-21_S2_QEMU首跑.md`、`notes/RISC-V内核启动详解-从start到start_kernel.md`。

## Q1（知识）配置开关

把主线 Linux 变成 rv32 + noMMU + M-mode 内核，需要哪几个配置项？7.2 里为什么没有 `rv32_defconfig`？

<details><summary>参考答案</summary>`CONFIG_ARCH_RV32I=y`（依赖 `NONPORTABLE`）、`CONFIG_MMU=n`、`CONFIG_RISCV_M_MODE=y`（依赖 `!MMU`，默认开）、`CONFIG_SMP=n`。`rv32_defconfig` 已删除，32 位改为 `arch/riscv/configs/32-bit.config` fragment（ARCH_RV32I + 32BIT + NONPORTABLE）。做法：`nommu_virt_defconfig` 打底，再合并 fragment——注意 `merge_config.sh` 要在构建目录里跑（否则会把合并结果写进源码树）。</details>

## Q2（知识）OpenSBI 墙

第一次 QEMU 启动卡在 OpenSBI 平台信息之后。为什么？`-bios none` 改变了什么？

<details><summary>参考答案</summary>QEMU virt 默认自带 OpenSBI：它在 M 模式初始化后把内核切到 S 模式启动（`Domain0 Next Mode: S-mode`）。`CONFIG_RISCV_M_MODE=y` 的内核期待独占 M 模式，第一条特权指令就卡死。`-bios none` 跳过固件，QEMU 直接以 M 模式启动内核——noMMU 内核的标准跑法。</details>

## Q3（程序题）构建并启动

写出构建步骤（defconfig + fragment + merge_config.sh 的坑）和 QEMU 启动命令。预期日志最后一行是什么？

<details><summary>参考答案</summary>
```bash
cd /home/developer/linux-7.2
make ARCH=riscv CROSS_COMPILE=riscv64-linux-gnu- O=build-rv32 nommu_virt_defconfig
cd build-rv32 && ../scripts/kconfig/merge_config.sh -m .config <仓库>/s2/rv32-nommu.config
cd .. && make ARCH=riscv CROSS_COMPILE=riscv64-linux-gnu- O=build-rv32 olddefconfig
make ARCH=riscv CROSS_COMPILE=riscv64-linux-gnu- O=build-rv32 -j$(nproc)

qemu-system-riscv32 -M virt -m 128M -bios none \
  -kernel build-rv32/arch/riscv/boot/Image -nographic \
  -append "earlycon=uart8250,mmio32,0x10000000 console=ttyS0"
```
预期最后一行：`Kernel panic - not syncing: VFS: Unable to mount root fs on unknown-block(0,0)`（还没有 rootfs，S4 的事）。merge_config.sh 的坑：要在构建目录里跑，否则它把合并结果写进源码树 `.config`，kbuild 报「源码树不干净」。</details>

## Q4（代码题）head.S 启动路径

在 `arch/riscv/kernel/head.S` 里找出：关中断、清 .bss、PMP 设置、搭栈、DTB 地址、跳转 start_kernel。noMMU 构建会跳过哪两段？

<details><summary>参考答案</summary>关中断：`_start_kernel` 开头 `csrw CSR_IE/CSR_IP, zero`；PMP：M-mode 块里 `csrw CSR_PMPADDR0, a0` + `csrw CSR_PMPCFG0, a0`；清 .bss：`.Lclear_bss` 循环（`__bss_start`/`__bss_stop`）；搭栈：`la tp, init_task; la sp, init_thread_union + THREAD_SIZE`；DTB：`mv a0, a1`（或 `CONFIG_BUILTIN_DTB` 时 `la a0, __dtb_start`）；跳转：`tail start_kernel`（前面还有 `scs_load_current` / `soc_early_init`）。noMMU 跳过 `setup_vm` 和 `relocate_enable_mmu`（都在 `#ifdef CONFIG_MMU` 里）。</details>

## Q5（知识）PIE 与重定位

vmlinux 为什么是 ET_DYN？noMMU 的 PAGE_OFFSET 是什么？`.rela.dyn` 表和 `relocate_kernel()` 干什么？

<details><summary>参考答案</summary>ET_DYN = 按位置无关链接（PIE），配合 `-mcmodel=medany`（PC 相对寻址），代码/数据引用跟着运行地址走。noMMU 的 `PAGE_OFFSET = phys_ram_base`（恒等映射，虚拟地址 = 物理地址）。少数躲不开的绝对指针被链接器收进 `.rela.dyn`，`relocate_kernel()`（arch/riscv/mm/init.c）启动早期遍历表，给每个 `R_RISCV_RELATIVE` 项加上加载偏移。`.bss` 由 head.S 自己清。</details>

## Q6（程序题）导出 DTB

导出并反编译 QEMU virt 的 DTB，找出 memory / serial / clint / plic 节点，并和启动日志里的行对应。

<details><summary>参考答案</summary>
```bash
qemu-system-riscv32 -M virt -machine dumpdtb=/tmp/virt.dtb
dtc -I dtb -O dts /tmp/virt.dtb
```
`memory@80000000`（128MB）↔ `Memory: 126832K/131072K available`；`serial@10000000`（ns16550a）↔ `10000000.serial: ttyS0 at MMIO 0x10000000`；`clint@2000000` ↔ `clint: clint@2000000: timer running at 10000000 Hz`；`plic@c000000` ↔ `riscv-plic: plic@c000000: mapped 96 interrupts`。完整注释版见 `notes/QEMU-virt-DTB参考.md`。</details>

## Q7（迁移预告）搬真板（S3）

内核在 QEMU 跑通了。搬到 `rp2350a_minimal`：没有 OpenSBI，内存是 PSRAM `0x11000000`，串口是 PL011 @ `0x40070000`，定时器 SIO mtime，中断 XH3IRQ。要动什么、照什么形状、最可能踩什么坑、怎么验？

<details><summary>参考答案</summary>内核代码基本不动（M 模式已经对了）。要动：最小 DTB（`memory@11000000`、`serial@40070000` 配 pl011、chosen/stdout-path）+ 启动参数（`earlycon=pl011,mmio32,0x40070000 console=ttyAMA0`）+ bootloader（把 Image 拷到 PSRAM 基址、a1 传真 DTB 地址而不是 NULL；分区大小要装得下 2.7MB 的 Image）。形状：复用 S1 分区表版 bootloader + QEMU virt 的 DTB 结构。最可能踩的坑：跳过去一条日志都没有（DTB/console/加载地址不对）——先查 earlycon，再用调试器。定时器/中断是 S4/S5，S3 不碰，内核会在 console 之后的某处卡住，这本身就是 S3 的预期现象。验证：真板串口出 Linux banner。</details>
