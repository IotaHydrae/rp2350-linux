# S1 练习题：假镜像闭环

> 复习材料：`notes/学习记录/S1 · 假镜像闭环.md`、`notes/实验日志/`（S1 相关日志）。

## Q1（知识）ID 能读到 ≠ 地址空间能用

psram-test 打印出了 `psram size: 8388608`，自检却卡死。为什么 PSRAM 的 ID 能读到、往 `0x11000000` 写却失败？

<details><summary>参考答案</summary>读 ID 走 QMI 直通模式（纯寄存器操作），从不经过 `0x11000000` 地址空间；自检是第一次真正访问地址空间。坏芯片/时序问题下「读 ID 正常、写卡死」，两条独立驱动路径表现一致，换板后坐实。</details>

## Q2（知识）跳转协议

bootloader 跳转假镜像（或真内核）前，必须摆好哪三样？假镜像为什么能直接用 a0/a1？为什么假镜像的链接地址必须等于运行地址？

<details><summary>参考答案</summary>a0 = hartid、a1 = DTB 地址（S1 传 NULL）、可用的栈（sp）、入口地址。假镜像的 C 函数 `main_c(hart, dtb)` 按 RISC-V ABI 直接收 a0/a1 作前两个参数——协议白送。假镜像链接在 0x11000000（即运行地址），所有绝对引用在链接时焊死，所以链接地址必须 = 运行地址（内核不同，它是 PIE）。</details>

## Q3（读代码）find_fake_partition

`s1/partition-table/bootloader/main.c` 里：

```c
int rc = rom_get_partition_table_info(workarea, 0x8,
    PT_INFO_PARTITION_LOCATION_AND_FLAGS | PT_INFO_SINGLE_PARTITION);
if (rc != 3) { /* fail */ }
uint32_t first = (workarea[1] & PICOBIN_PARTITION_LOCATION_FIRST_SECTOR_BITS) >>
                 PICOBIN_PARTITION_LOCATION_FIRST_SECTOR_LSB;
```

返回值 3 是什么意思？`workarea[1]` 里是什么？为什么 `rc != 3` 就当「没有分区」？

<details><summary>参考答案</summary>`rom_get_partition_table_info` 把请求的信息以字为单位写进缓冲区并返回写入的字数。带 `PT_INFO_SINGLE_PARTITION` 时写 3 个字：`workarea[0]` = 标志、`workarea[1]` = 分区位置与标志（首/末扇区字段）、`workarea[2]` = 更多标志/ID。rc != 3 说明 bootrom 没产出预期的单分区记录，按「无可用分区」处理。</details>

## Q4（程序题）挪分区

把 FAKE 分区从 64K 挪到 1MB。要改哪些文件/命令？bootloader 日志的第一行预期变成什么？

<details><summary>参考答案</summary>只需改 `s1/partition_table.json`：`"start": "1M"`。bootloader 读分区表（代码不用动），烧录仍是 `picotool load -fv -p 0 build/s1/fake-image.bin`（分区 id 没变）。预期日志：`partition sectors [256, ...] -> flash 0x10100000, ...`（1MB = 第 256 扇区）。提醒：烧完带分区表的 bootloader 后，要重启设备再进 BOOTSEL，picotool 才能读到分区表。</details>

## Q5（汇编）读 _start

```asm
11000000 <_start>:
11000000: 117ff137  lui  sp,0x117ff
11000004: 28b9      jal  11000062 <main_c>
11000006: a001      j    11000006
```

指出：哪条是摆栈、哪条是调用 C 函数、哪条是死循环。为什么这里完全不动 a0/a1？

<details><summary>参考答案</summary>`lui sp,0x117ff` → sp = 0x117ff000（栈放 PSRAM 顶部）；`jal main_c` → 调用，返回地址进 ra；`j 11000006` → 死循环（main_c 返回才会走到）。a0/a1 原封不动，因为它们已经分别是 hartid/DTB——正好是 C 函数前两个参数的位置。</details>

## Q6（程序题）给假镜像加自检

修改 `s1/partition-table/fake-image/main.c`：向 `0x11001000` 写 `0x55AA55AA`，读回比对，打印 PASS/FAIL。预期 UART 输出是什么？

<details><summary>参考答案</summary>
```c
volatile uint32_t *p = (volatile uint32_t *)0x11001000;
*p = 0x55AA55AA;
uart_puts(*p == 0x55AA55AA ? "[Fake Image] memcheck PASS\r\n"
                           : "[Fake Image] memcheck FAIL\r\n");
```
预期输出（放在死循环之前）：
```
[Fake Image] done, looping.
[Fake Image] memcheck PASS
```
</details>

## Q7（知识/坑）picotool 的地址

为什么 `picotool load -fv -o 0x10000 build/fake-image.bin` 报 `invalid memory range`？`-o 0x10010000` 和 `-p 0` 有什么区别？烧完带分区表的固件后第一次 `-p 0` 为什么失败、怎么解决？

<details><summary>参考答案</summary>`-o` 是绝对 XIP 地址；0x10000 低于 flash XIP 基址 0x10000000，非法。`-o 0x10010000` 按地址写 flash 偏移 64K；`-p 0` 按分区 id 0 写（由内嵌分区表定义），不用手动算地址。带内嵌分区表的固件烧完后，设备要在重启后再进 BOOTSEL，picotool 才能读到分区表（它按启动时缓存的分区表判断），否则报 `There is no partition table on the device`。</details>
